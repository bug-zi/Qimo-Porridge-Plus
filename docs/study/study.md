# study/ 学习文档库总文档

> 本库服务于"人借项目学习 Python 全栈"：不追求 AI 喂知识，而是引导人在真实项目中
> 建立通透认知。规则见 `../project/README.md`。

## 结构与分工

| 文件夹 | 放什么 | 谁写 |
|---|---|---|
| `guide/` | 稳定学习路线，以及实际阶段/课次/会话推进记录、代码锚点和练习 | AI 编写维护，人使用与裁决 |
| `patterns/` | 一个真实遇到的概念→本项目文件/函数/调用链/字段/理由/练习 | 人提问驱动，AI 起草，人阅读确认 |
| `log/` | 用户自己的复述、心得、卡点、错误猜测和下一步 | **人执笔为主**；AI 仅经明确授权协助整理并标注 |

## 当前学习状态

- 阶段：🧊 项目冻结期 · 学习起步（2026-08-29 起，见看板）
- 主路线：`guide/项目学习指南.md` 的六阶段（A 分层骨架 → B 模型调用 → C 课程生成流水线
  → D 数据与领域服务 → E 前端 → F 辅助系统+总装）
- 学习与文档联动：路线推进记入 guide；学到概念后在 patterns/ 起草一篇对照；用户复述或确认后才标记“已过关”。
- 学完一个域 → 补全该域 design/designs-specs（该域的“毕业考”）；只有用户确认过的理解才回流域文档导读。
- 三类文档互相链接，不重复全文：guide 记录“走到哪里”，patterns 记录“概念是什么”，log 记录“我是否真的理解”。
- 带教交流补充来源标记：AI 讲解记录不等于用户掌握；用户复述/反馈只记录实际表达；用户明确确认后才可标记“已过关”或回流域导读。
- 学习对话优先采用“项目老开发者带新人”模式：一轮一个问题，先为什么后怎么做，最后交还继续/换例子/暂停的选择权。

## patterns/ 写作模板

```markdown
# <概念名>（如：依赖注入）
## 概念是什么（通俗+严谨各一段）
## 在本项目中的实例（文件/函数/代码片段，给锚点）
## 为什么这里用它（不用会怎样）
## 延伸问题（可选）
```

已登记概念：（暂无——第一个来了就补，如 SSE、中间件、生产者消费者、fencing token、拓扑排序）

## 学习 log 写作建议

一天一文件 `YYYY-MM-DD.md`，只记三样：今天学了什么域/链路、卡壳与想通的地方、
明天打算学什么。AI 的开发日志在 `../log/`，两边不混写。
