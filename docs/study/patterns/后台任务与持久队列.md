## 概念是什么

后台 job 是先登记为任务记录，再由后台执行者异步处理，并持续保存状态、进度、结果和错误的长时间任务。它与普通函数的区别是：调用者不必一直等待函数返回，可以之后查询任务状态。

## 在本项目中的实例

- `backend/app/agent_runtime.py:562`：`_claim_job` 从 `agent_jobs` 表寻找 queued 任务，领取后改为 running。
- `backend/app/agent_runtime.py:691`：`AgentJobWorker`；`_run` 在 709 行持续领取并执行任务。
- `backend/app/agent_runtime.py:609`：成功完成后写入 completed。
- `backend/app/agent_runtime.py:627`：失败时按 attempts/maxAttempts 决定重试或 failed。
- `backend/app/agent_runtime.py:650`：续租；680 行心跳。

基础状态：

```text
queued → running → completed
                  ↘ failed
running → queued（失败但仍可重试）
```

## 为什么这里用它

课程生成会调用外部模型并持续较长时间。如果让一个 HTTP 请求一直等待，容易超时、无法恢复，也难以向用户展示进度。持久 job 让后端可以异步执行，前端另行查询。

## 常见误解与边界

- 后台 job 不等于自动多进程并行；本项目的 `AgentJobWorker` 按单进程单线程消费设计。
- job 记录本身不是课程正文；课程正文主要落在 workspace.json。
