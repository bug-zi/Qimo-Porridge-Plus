## 概念是什么

双存储是根据数据形态把信息分别放进不同存储：结构化、需要查询和并发管理的小数据放数据库；层级深、内容大、整体读改写的文档放 JSON 工作区。

## 在本项目中的实例

- SQLite：`courses`、`agent_jobs`、`agent_runs`、`artifacts` 等表，管理课程索引、任务、运行史和 checkpoint 元数据。
- `backend/app/workspace.py:46-47`：每门课程对应 `backend/data/courses/<course_id>/workspace.json`。
- `load_workspace` 在 335 行读取 JSON，并进行 revision、内容质量和迁移维护。
- `save_workspace` 在 399 行通过文件锁、revision 检查和原子写入保存。

## 为什么这里用它

课程正文包含 tasks、studyGuide、practiceQuestions、mockQuestions、knowledgePoints 等复杂嵌套内容。把它们全部拆成数据库表会增加映射和维护成本；把队列状态放 JSON 又不利于查询、事务和 Worker 竞争。

## 常见误解与边界

- workspace.json 不是简单配置文件，而是一门课程的复杂学习文档。
- SQLite 与 workspace.json 不是重复保存同一份课程正文，而是分别管理系统状态和课程内容。
