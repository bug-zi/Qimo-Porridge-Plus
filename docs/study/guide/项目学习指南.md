# 期末粥++ 项目学习指南（如何吃透这个项目）

---

## 0. 学习哲学（先立规矩）

1. **自顶向下，链路优先。** 先跑通"一个功能在多层间怎么穿"的完整故事，再钻细节。
   孤立地背文件清单没有意义——理解是靠链路串起来的。
2. **运行中学习。** 起服务、点按钮、看日志和 SQLite,把静态代码和动态行为对上号。
3. **不做全知。** 目标是主干通透 + 长尾可查,不是每个文件都读过。深度的分配要跟着
   你未来的计划走(生成提速/风格/缓存正好覆盖核心域)。

## 1. 新人带教模式（默认协作方式）

从本次交流起，学习不按“AI 一次性讲完一阶段”推进，而按项目老开发者带新人入职的方式进行。六阶段 A→B→C→D→E→F 仍保留，它是路线地图，不是每轮必须执行的课程表。

### 每轮带教结构

1. **本轮目标**：只解决一个明确问题。
2. **项目语境**：先说这个问题在产品中为什么存在。
3. **总图定位**：说明它位于前端、路由、服务、存储或 AI 工作流哪一层。
4. **真实代码链路**：给出路径、函数名和大致行号。
5. **设计原因**：讲清收益、代价和不这样做的后果。
6. **轻量检查点**：请新人用自己的话复述或追踪一个小问题。
7. **交还控制权**：由新人选择继续深入、换例子、补概念或暂停。

### 讲解节奏

- 默认一轮只讲一个概念加一条短链路，不倾倒整模块。
- 先讲项目里的具体故事，再给类比，最后补严谨术语。
- 大文件先找入口、调用方和数据契约，不从第一行读到最后一行。
- 明确区分代码事实、设计推断、历史背景和已知债务。
- 新人觉得负担大时退回上一层；觉得顺畅时再增加深度。
- 每轮只给必要的下一步，不提前布置完整阶段任务。

### 新人可以随时发出的指令

“换一种方式讲”“先解释这个名词”“只讲调用链”“为什么这样设计”“我先复述一下”“暂时停在这里”。这些指令优先于原定路线。

## 3. 学习路线（六个阶段,建议 2~4 周,与你的 Python 全栈学习互喂）

### 阶段 A:一次请求的一生——FastAPI 分层骨架(1~2 天)

**学什么**:一次普通读请求怎么穿过中间件→路由→数据库再回来。

- `main.py` 全文(277 行,小):lifespan 启动序列、中间件栈、router 挂载
- `routers/deps.py`:`get_connection` / `current_owner_id` / `require_course_ownership`
- 挑一条最简路由精读,如 `routers/courses.py` 的 GET /api/courses
- 对照前端:`api.ts` 里对应的调用函数 → `apiClient.ts` 的 fetch 封装

**练**:浏览器 F12 Network 面板,点一个页面功能,找到对应 XHR,从 URL 反查到后端路由函数。
**知识点映射**(Python 全栈):FastAPI 路由与 Depends 依赖注入、Pydantic 模型、SQLite 连接管理、CORS/JWT 中间件原理。
**过关标准**:任点一个按钮,能一路指到路由函数,并说清 owner 校验发生在哪一行。

### 阶段 B:模型调用层——全项目最核心基础设施(2~3 天)

**为什么先学它**:你计划的"生成提速"优化,全部落在这一层和它的调用方。

- `model_client.py`(770 行)按调用链自顶向下读(project.md §3.4 的那张图就是阅读地图):
  `_model_json` → `_model_completion` → `_model_providers`(主备 failover 顺序、熔断) →
  `_provider_request` → `_read_sse_response`(流式、30s 首 token 超时)
- 读 `model_usage.py` 看一次调用的遥测怎么记
- 重点理解三段"为什么":为什么改流式+首 token 超时(300s 误杀史,CLAUDE.md)、
  为什么有熔断、为什么"主备均不可用"要立即中止整轮生成(content_workflow.py:350 附近)

**练**:在设置页点一次"连通性测试"(probe_model_chat),后端控制台看日志;
生成一节课时打开 `model_usage` 数据,数一数这节课烧了几次模型调用、各阶段多少。
**知识点映射**:requests 流式请求、SSE 协议、重试与退避算法、故障转移模式。
**过关标准**:画出一次 `_model_completion` 的完整流程图(含重试、failover、超时三个分支),不看资料。

### 阶段 C:课程生成流水线——产品心脏(3~5 天,最重的一站)

**学什么**:从"点生成按钮"到"卡片翻成开始学习"的完整链路(project.md §4.1)。

拆成四口咬:

1. **队列**:为什么走后台 job 而不是 HTTP 同步?精读 `agent_runtime.py` 的
   AgentJobWorker._run / _claim_job / _renew_job_lease / has_agent_job_ownership,
   理解 lease fencing 解决的"双重执行"事故(132e3e1,看板有案)
2. **编排**:content_workflow.run_content_workflow 全文精读。四个 checkpoint 机制
   (planner/lesson/questions/mock 签名缓存)是"缓存优化"的直接对象
3. **单节生成**:lesson_generation.LessonBuilder.build + question_generation +
   content_validation(硬校验) + content_patches(定向修补)
4. **落盘与可见**:on_progress 回调 → workspace 逐节写入 → 前端轮询

**练**(最重要的一次实操):真实生成一节课,同时开着三个窗口观察——前端进度卡、
SQLite 的 agent_jobs/agent_runs/artifacts 表、workspace.json 的变化时间线。生成完
把 artifacts 表里的 checkpoint 内容导出来看。
**知识点映射**:生产者-消费者队列、租约与 fencing token(分布式系统经典概念!)、
检查点/签名缓存模式、分层校验(模型自修 vs 确定性拒绝)。
**过关标准**:能白板讲出"生成下一课"从点击到完成的 10 步以上流程,并指出每个环节失败时用户会看到什么。

### 阶段 D:数据与领域服务——workspace 双存储模型(2~3 天)

- `workspace.py`:load/save/文件锁/revision;对比 SQLite 行,理解为什么大文档放 JSON 文件
- `paths.py`(24 行,但读懂它的注释=理解测试隔离设计)
- 挑两个域精读:`practice.py`(判分/掌握度,业务味浓,好读)和 `strategy.py`(策略文档版本化)
- `study_scheduler.py`:纯函数 DAG 调度器,数学味重,当算法练习读

**练**:做一次练习题,在 SQLite 里找到自己的作答记录,在 workspace.json 里追踪掌握度变化。
**知识点映射**:文件锁与并发、数据分层存储策略、拓扑排序应用。
**过关标准**:说清"哪些数据在库里、哪些在 workspace.json、为什么这么分"。

### 阶段 E:前端巨石与状态流(2~3 天)

- `App.tsx` 的顶层状态设计 → 各 View 的职责
- `ModuleView.tsx` 不逐行读(5598 行):用"找链路"方式——划词反馈、练习提交、
  自测判分各找一条"组件事件 → api.ts 调用"的链
- `types.ts` 浏览一遍:它是前后端契约的镜子,反过来加深对 workspace 结构的理解
- `useStrategyGenerationJob` + `features/courseGeneration/generationStatus.ts`:轮询状态机

**练**:F12 里盯着一次课程生成的网络请求序列(每 1.8s 一次轮询),对照状态卡变化。
**知识点映射**:React 状态提升、自定义 hook、SSE 客户端、轮询 vs 推送。
**过关标准**:任指页面上一个交互,能说出它的事件处理器在哪个文件、调了哪个 API。

### 阶段 F:辅助系统速览 + 总装(1~2 天)

- 速览:knowledge_service(RAG 检索怎么给生成供料)、material_parser(解析级联)、
  course_feedback_service(划词反馈闭环)、agent_chat(SSE 对话)
- **总装检验**(整个学习的毕业考):
  1. 白纸画出全系统架构图(不看文档),再对照 project.md 查漏
  2. 把你计划的四个优化方向逐一定位:生成提速→阶段 B+C;语言风格多样化→course_style_templates
     + content_prompts;课程设计完善→planner prompt + 校验;加载缓存→checkpoint + 前端缓存
  3. 挑一个方向写一页纸"现状+优化思路"——这就是你未来开发计划的雏形

## 3. 与 AI 协作学习的姿势(本项目的核心玩法)

### 该问 AI 什么

- [ ]  **链路追溯**:"XX 功能从前端到数据库走了哪些代码?"——AI 用 codegraph 一查即答,省你大量 grep
- [ ]  **代码讲解**:贴一段代码问"这段为什么这么写,不这么写会怎样"
- [ ]  **历史考古**:"lease fencing 是修什么 bug 的?"——AI 能结合 git log 和看板讲出事故史
- [ ]  **概念补课**:读到不懂的 Python/Web 概念,当场问,别攒

### 不该让 AI 干什么

- ❌ 不要让 AI 一次性生成全部模块的详细讲解文档——那是"喂",不是"学"(你自己已经想明白了这点)
- ❌ 学习期间保持项目冻结(你的决定),AI 只解释不改动

### 学习成果的沉淀方式

每学完一个域,让 AI 把"你问过的好问题 + 卡过的点"沉淀为一篇该域的导览文档
(`designs-specs.md` 域文档体系,见 `docs/project/README.md`),逐步搭起上一轮讨论的人机交互框架。**你的问题就是最好的文档素材**——
问过的困惑不会蒸发,会成为你未来审阅 AI 改动时的底气。

## 5. 风险与提醒

- **数据安全**:学习期的所有实操用测试课程;`exam_booster.db` 是真实学习数据,任何脚本不得清库(CLAUDE.md)
- **别陷进细节**:目标是"通透"不是"全知"。读不下去的文件(如 ModuleView 全文)标记跳过,链路通了就行
- **project.md 会过时**:它锚定 2026-08-30 的代码快照。发现文档与代码不符时告诉 AI,这正好是
  "实现→文档回流"闭环的第一次演练
- **学习与开发解耦**:学完之前不增不改功能;学习中发现的 bug 记到看板,不顺手修(那是新模式运行后的第一批实战)
