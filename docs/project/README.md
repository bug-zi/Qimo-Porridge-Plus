# docs/project 机制正本

> 本文件是 `docs/` 文档库的机制正本：权责划分、spec/plan 存放与归档机制、项目特有机制，由 **AI 维护**。
> 结构变更（增删目录、改命名规则、改生命周期）必须先改本文件，再动目录。
> 人是所有设计裁决的唯一所有者；AI 负责起草、加工、同步与记录，不拥有裁决权。
> 前身《docs.md 宪法》（v1.0~v1.3，2026-08-29~09-24）已于 2026-09-24 按 docs-creator 体系重构并入本文件；旧库整体冻结于 `doc/`（只读，永不改动），历史可溯源。

## 1. 文档库结构

```
docs/
├─ log/                  ← 开发日志（AI 维护，一天一文件 YYMMDD.md，append-only）
├─ project/              ══ 开发文档库 ══
│  ├─ README.md          ← 本文件（机制正本）
│  ├─ project.md         ← 项目总介绍 + 域地图（开发者主导）
│  ├─ DEV_BOARD.md       ← 实时看板（状态真源，每会话结束刷新）
│  ├─ 新功能开发区.md     ← 开发者记新功能需求（AI 立项实施后按轮归档）
│  ├─ 优化建议区.md       ← 开发者记优化建议（AI 实施后按轮归档）
│  ├─ 问题疑惑区.md       ← 开发者记疑惑（AI 不主动查阅，指名答疑）
│  ├─ 临时草稿（待写入）.md ← 开发者草稿本（AI 不读取）
│  ├─ idea/              ← idea 阶段模块的 spec/plan 暂存（开发者领地，AI 只动自己产出的文件）
│  ├─ 全局/              ← 系统级/跨模块方案（spec/plan）+ archive/（方案归档 + 错误档案 + 实验稿）
│  └─ modules/           ← 功能域 ×29（一域一文件夹：可见功能域 ×20 + 引擎域 ×9）
└─ study/                ══ 学习文档库 ══（结构原样保留，规则见 study/study.md）
   ├─ study.md / guide/ / patterns/ / log/
```

域清单（可见功能域 20 + 引擎域 9）与中英对照见 `project.md` 域地图。

## 2. 权责表

| 内容 | 维护方 | AI 的角色 |
|---|---|---|
| `<模块>/design.md`（modules/ 下各域） | 开发者主导 | 可提建议；经审核通过才可修改，**不得擅自改写** |
| `<区域>/<模块>/designs-specs.md` | **AI 生成并维护** | 基于 design.md 严格生成，是开发的直接依据；开发者仅简单审核 |
| `project.md` 项目总介绍 | 开发者主导 | 可提建议；经审核通过才可协助完善 |
| 本 README（机制正本） | **AI** | 随体系演进更新 |
| `log/<YYMMDD>.md` 开发日志 | AI | 一天一文件；小节下首行 `> 创建于 YYYY-MM-DD HH:MM`（date 实取，不估不编） |
| `DEV_BOARD.md` 实时看板 | AI 职责 | 每个会话结束必须更新（义务同 CLAUDE.md） |
| `全局/archive/` 错误档案 | AI 职责 | 遇错自动建档；全量持久，只进不改（索引见 archive/archive.md） |
| `新功能开发区.md` | 开发者记录 | AI 据此 brainstorming 立项并实施；完成后条目勾选、按轮归档 |
| `优化建议区.md` | 开发者记录 | AI 据此实施优化；实施后按轮归档 |
| `问题疑惑区.md` | 开发者记录 | **AI 不主动查阅**；开发者指名时才读并答疑，解答后按轮归档 |
| `临时草稿（待写入）.md` 与 `idea/` | 开发者 | AI 不读取、不修改；例外：AI 产出的 spec/plan 可存 `idea/<模块>/`，只动自己产出的文件 |
| `全局/` 系统级方案 | 权责同模块文档 | AI 起草 spec/plan，落地/废弃后归档 |
| `study/` 学习库 | 见 `study/study.md` | guide AI 维护 / patterns AI 起草人确认 / log 用户执笔为主 |
| 各子目录同名说明 md | 随目录权责 | 说明该目录功能与用法；新建子目录时随建随补 |
| Git 操作 | 开发者 | **禁止 AI 自主执行任何 git 操作**（CLAUDE.md 铁律） |

## 3. 工作流程

开发者写 `design.md`（需求正本）→ AI 严格依据生成 `designs-specs.md`（开发直接依据）→ AI 按 specs 开发 → AI 记日志、更新看板 → 落地后耐久结论回流 design/specs，过程文档归档。

需求入口：新功能 → `新功能开发区.md`；优化 → `优化建议区.md`；疑惑 → `问题疑惑区.md`；未成型草稿 → `临时草稿（待写入）.md`。较大变更仍走 CLAUDE.md「先方案后实施」铁律。

## 4. spec / plan 机制

brainstorming / 写计划会话产出的**设计记录（spec）与实施计划（plan）**按所属模块就地存放，不设独立集中目录：

| 文档所属 | 存放目录 |
|---|---|
| idea 阶段模块（尚无正式 design.md） | `idea/<模块>/` |
| 已立项模块 | `modules/<域>/` |
| 跨模块 / 系统级 | `全局/`（或对应区域目录） |

- 命名 `YYYY-MM-DD-<主题>-design.md` / `-plan.md`（主题中文短语，日期前缀保证唯一），归档不改名。
- spec 与 plan 同目录混放，plan 头部 `**Spec:**` 字段互指；小改动可只有 spec。
- plan 顶部状态行：`状态：进行中 / 已落地 / 已废弃（原因）`。
- 落地判定（项目约定）：有代码改动以验证三件套全绿为准；纯文档以开发者验收确认为准。

## 5. 归档机制（全自动 + 开发者口令兜底）

| 判定 | 动作 |
|---|---|
| 落地（日志/状态行记录实施完成） | 移入所属目录 `archive/`，状态行追加 `- 已归档：YYMMDD 随 <主题> 落地` |
| 废弃（**开发者明说才废弃**，AI 不自行判定） | 移入 `archive/`，状态行标注 `- 已归档：YYMMDD 废弃（<原因>）` |
| 待实现 / 进行中 / 依据不明 | 不动；拿不准报告开发者 |

**固定四步**：① `mv` 入 `archive/` 不改名 → ② 状态区追加归档行 → ③ 全库检索旧路径、更新**活动文档**引用（历史日志不改）→ ④ 当日日志记一笔。

- spec 归档时其对应 plan（`**Spec:**` 指向它者）一并归档；idea 阶段模块正式立项迁移目录时 spec/plan 一并迁入。
- 三区（新功能开发区/优化建议区/问题疑惑区）**按轮归档**：AI 每完成一轮，把该轮全部条目作为一组，在归档区/已完成区**顶部**新增 `### 第N轮（YYMMDD）：本轮主题`；条目保留原始描述并附完成/立项说明或问答全文；轮次从第 1 轮起全项目连续编号只增不减，新轮永远插最上方。
- 触发时机：写日终日志记录「实施完成」时；写新 spec/plan 清点所属目录时；开发者说「归档一下」为兜底。
- **归档只是位置变化，文件永不删除**。回改通道：archive 内直接改或移回，日志记录。

## 6. 域内双文档与回流

每个域文件夹内固定两件套：

| 文档 | 内容 | 模式一：已有模块（考古） | 模式二：新功能（规划） |
|---|---|---|---|
| `design.md` | 定位/关键决策与理由/不变量/禁区/设计异议（契约） | AI 从代码+git 史逆向起草 → 人审定 | 源自 spec/方案 |
| `designs-specs.md` | 文件清单/调用链/数据契约/测试锚点/导读（事实） | 从代码生成，随代码同步 | 先写 specs 指导实现，落地后随代码同步 |

**冲突处理**：specs 与代码冲突 → 以代码为准并更新 specs；design 与代码冲突 → 在该域 designs-specs.md「设计异议」节记录，交人裁决（改文档、改代码、或记为已知债务），不许悄悄单改一边。

**回流**：spec/plan 或方案落地时，耐久结论必须合并回对应域 design.md（决策）与 designs-specs.md（事实）——这一步没做完，任务不算完成。

## 7. 错误档案库（全局/archive/）

- **AI 遇错自动建档义务**：任何会话遇到（或被告知）真实错误——运行失败、测试红灯、行为异常、构建崩溃——必须在 `全局/archive/` 建档（`YYYY-MM-DD-<英文slug>.md`，规则与模板见 archive/archive.md 所附 bugs.md），无论是否顺手修复。
- 与看板 🐛 区分工：错误档案全量持久（不删）；看板只留活跃/待验证条目。
- 状态流转：🔴 待修复 → 🟡 已修待验证 → ✅ 已关闭（附 commit）；⚪ 暂不修（附理由）。
- 误报/根因纠正：原档案标注更正并保留原文，不删文件。

## 8. AI 生成语言规范（用户执笔，AI 只读遵守）

> 本节是文档库的**文风宪法**：约束 AI 在写作与交互中的表达方式。条目由用户手动编写存入——用户专区；AI **不得改写、删除、替用户预填**任何条目，规范缺失也不许自行起草塞入，只能提醒用户可自行补充。若 AI 认为某条规范需要调整，在会话中口头提议，由用户决定。
> 适用范围：docs/ 库内全部 AI 产出（design.md / designs-specs.md / log / 看板 / 三区 / spec-plan / bugs / study 侧文档）以及 AI 与用户围绕文档工作的日常交互表达。与本文件其他节冲突时，本节优先。
