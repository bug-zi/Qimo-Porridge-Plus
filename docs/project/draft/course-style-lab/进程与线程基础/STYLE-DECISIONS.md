# 课程样式决策记录

> 用途：记录用户对样稿的明确选择。只有用户确认的决定才会进入最终“80 分 Prompt”。  
> 状态说明：**已确认**、**待确认**、**已否决**。

## 一、已确认的强规则

| 维度 | 决定 | 证据来源 | 状态 |
| --- | --- | --- | --- |
| 句式 | 禁用“不是……而是……”及其机械变体，优先使用直接、正向定义 | 课程历史反馈规则 | 已确认 |
| 内容转换 | 从概念转到步骤、总结或易错点时，应让读者自然理解这一段的用途 | 课程历史反馈规则 | 已确认 |
| 事实边界 | 风格规则不得修改事实、公式条件、资料依据和考试范围 | 当前课程 Prompt | 已确认 |
| 表述强度 | 涉及实现差异的结论保留“通常、常见语境、取决于实现”等限定 | 当前课程资料与审查 | 已确认 |

## 二、待用户确认的宏观结构

### 1. 讲解从哪里开始

确认采用 **具体问题驱动**：先提出“程序运行后系统怎样管理、一个应用怎样同时推进多项任务、CPU 切换时要保存什么”等问题，再自然引出程序、进程、PCB、线程和切换。

状态：**已确认**。

### 2. 讲解的详细程度

确认采用 **速成但讲清因果**：删除次要实现细节和过长的学术边界说明，保留理解结论所需的“为什么”以及防止答错所需的限定。

状态：**已确认**。

### 3. 小标题密度

确认 **保留问题式标题**，用标题带领读者沿问题推进；避免无意义的层级嵌套。结尾只保留一条完整因果链，不叠加口诀、重复表格和多轮总结。

状态：**已确认**。

### 4. 总结与口诀

确认结尾 **只保留因果链**。局部可保留真正帮助理解的关键句；删除同义口诀、多轮总结和为了结构完整而添加的重复收束。易错点优先放在相关概念附近。

状态：**已确认**。

## 三、待用户确认的例题结构

确认采用 **一个主场景综合例题，加两到三道独立变式**。主场景负责串联程序、进程、PCB、线程共享/私有和切换；独立变式检验能否迁移到新场景。

还需确认：

- 每题是否都需要“分析—解答—结论”；
- 是否保留“得分抓手”；
- 例题是否应出现略超前内容，例如用竞态帮助理解线程共享；
- 答案更偏考试标准答案，还是老师讲题式答案。

状态：**待确认**。

## 四、待用户确认的自测结构

确认采用 **少量客观题＋两道场景简答**：约 5 道客观题检查概念，再用 2 道场景题检查理解和迁移。答案统一采用 **先给结论，再解释决定答案的关键原因**；避免冗长讲题和机械重复题干。

状态：**已确认**。

## 五、观察项：当前 V0.1 可能存在的 AI 味

以下项目并未判定为错误，等待用户圈定：

- 高频使用“可以记住”“一句话概括”“最终记住”；
- 段落结构过于整齐；
- 每个模块都倾向于给结论和边界；
- 表格较多；
- “阅读目标、最低达标线、得分抓手、自评标准”等产品化标签较多；
- 对实现差异的限定可能打断速成课节奏；
- 讲解、例题和答案之间存在部分重复。

## 七、生成 80 分 Prompt 的门槛

满足以下条件后才生成正式 Prompt：

- [ ] 用户确认讲解的起点与主线；
- [ ] 用户确认详略程度和标题密度；
- [ ] 用户确认总结、易错点和边界说明的放置方式；
- [ ] 用户确认例题编排方式；
- [ ] 用户确认自测题型与答案风格；
- [ ] 至少完成一轮具体文字修改；
- [ ] 从最终文档中提取足够的正例和反例；
- [ ] 用户明确表示样稿已达到可接受的 80 分基线。
