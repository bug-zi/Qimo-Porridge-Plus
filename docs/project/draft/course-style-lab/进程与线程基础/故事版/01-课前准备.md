# 进程与线程基础｜课前准备

> 故事线索：小林一边用浏览器找资料，一边下载课程文件。  
> 本节关键词：程序、进程、PCB、线程、资源共享、上下文切换。

## 浏览器忙起来的那个晚上

晚上，小林打开浏览器准备课程展示。十几个网页已经排在标签栏里，视频正在播放，一份课程文件也在下载。她又点开一个新页面，浏览器依然能响应。

“屏幕上明明只有一个浏览器窗口，它怎么能同时忙这么多事？”小林盯着下载进度条想。

站在操作系统的角度，这个场景可以先画成这样：

```text
磁盘里的浏览器文件
    ↓ 双击启动
浏览器进程
    ├─ 界面线程：负责响应点击
    ├─ 网络线程：负责接收网页和下载数据
    └─ 渲染线程：负责把内容显示到页面上
```

她顺手把疑问记了下来：

- 浏览器安静地躺在磁盘里，和它真正运行起来，有什么区别？
- 浏览器占用的内存、打开的文件和网络连接，由谁统一管理？
- 下载文件时页面还能正常操作，这些任务是怎么一起推进的？
- CPU 执行到一半去处理别的任务，回来后怎么知道刚才做到哪了？

这些问题，正好把今天要认识的几个标准术语串在了一起。

## 程序：还没开始运行的代码

小林先看向磁盘里的浏览器可执行文件。它保存着指令和数据，却还没有真正执行，也没有自己的运行状态。这就是**程序**：保存在磁盘等介质上的指令和数据。

如果把它比作菜谱，步骤虽然已经写好，厨师却还没动手，厨房里也没有正在进行的烹饪过程。

## 进程：程序运行起来的这一趟

小林双击图标后，操作系统加载程序，并为这次运行安排地址空间、内存、文件等资源。这一次实际的运行，就是**进程**。

程序与进程的关系，就像“游戏安装包”和“这一局正在进行的游戏”。同一个安装包可以反复启动；同一款编辑器启动两次时，系统也可能创建两个进程。它们使用相同的程序代码，却各自保留运行状态和资源环境。

## PCB：操作系统手里的进程档案

电脑里同时有许多进程，操作系统不能凭印象管理它们。它会为每个进程维护一份可以查询和修改的管理记录，这就是 **PCB（进程控制块）**。

小林把 PCB 想成一张进程档案卡，其中通常记录：

- 这是哪个进程：进程标识；
- 它现在是什么状态：进程状态和调度信息；
- 它刚才执行到哪里：程序计数器和寄存器现场；
- 它正在使用什么：内存、进程级打开文件资源等信息。

进程暂停时，操作系统保存必要信息；进程再次获得 CPU 时，再依照这些信息从原处继续。这有点像游戏存档：先记住进度，之后才能接着玩。

教材常说“**PCB 是进程存在的唯一标志**”，强调的正是操作系统通过这份档案识别和管理进程。

## 线程：进程里的任务执行线

下载仍在继续，小林却还能点击页面。原因是一个浏览器进程里不只需要做一件事：它既要响应点击，又要加载网页，还可能在后台下载文件。若所有任务只排成一条长队，下载稍微卡住，其他工作也可能跟着等待。

**线程**是进程内部的一条执行线。一个进程至少有一条线程，也可以有多条线程分别推进不同任务。

回到浏览器中，界面响应、网络加载和页面渲染是三类不同任务，可以由不同线程各自推进。即使网络加载暂时等待，界面线程仍有机会响应小林的操作。

## 资源共享：同一进程里的线程共同使用什么

这些线程属于同一个进程，因此通常可以共享：

- 地址空间和程序代码；
- 全局变量、静态数据和堆；
- 进程级打开文件资源。

比如，下载线程更新进度数据后，界面线程可以直接读取这份数据并刷新进度条，不必为两条线程各准备一份副本。

不过，共享也有代价。若两条线程同时修改同一份数据，就像两个人同时改一张订单，可能出现数据不一致。后面学习同步互斥时，会专门处理这个问题。

## 上下文切换：CPU 换任务前先记住进度

这时，小林又想到最后一个问题：CPU 去执行别的任务后，怎么回来接着做？

CPU 从当前任务切换到另一个任务前，需要保存当前任务的运行信息，再恢复下一个任务的运行信息，这就是**上下文切换**。像写作业时临时接电话，离开前记下做到哪一步，回来才接得上。

同一进程内的线程共享地址空间，切换时通常主要处理线程自己的程序计数器、寄存器和栈。跨进程切换还可能更换地址空间和内存管理上下文，所以同进程线程切换通常更轻。

但“更轻”并不等于没有开销。只要更换执行对象，保存和恢复现场的工作就仍然存在。
