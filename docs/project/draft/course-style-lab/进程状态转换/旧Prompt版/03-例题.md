# 进程状态转换｜例题

## 主例题：打印任务经历了哪些状态？

某进程 P 初始位于就绪队列，之后依次发生以下事件：

1. 调度程序选中 P；
2. P 运行一段时间后申请打印机，打印机暂不可用；
3. 打印机可用，系统唤醒 P；
4. 调度程序再次选中 P；
5. P 的时间片用完，但仍可继续执行。

请回答：

1. 写出 P 的完整状态变化链，并标明每一步的触发原因。
2. 第 3 步能否直接写成“阻塞态 → 运行态”？
3. 第 5 步为什么进入就绪态而没有进入阻塞态？

### 解答

**第 1 问结论：** 状态变化链为：

```text
就绪态 → 运行态 → 阻塞态 → 就绪态 → 运行态 → 就绪态
```

**原因：** P 被调度并获得 CPU，先由就绪态进入运行态；申请暂不可用的打印机后必须等待，由运行态进入阻塞态；打印机可用使等待条件解除，P 被唤醒并进入就绪态；再次被调度后进入运行态；时间片用完时 P 仍具备运行条件，因此回到就绪态。

**第 2 问结论：** 通常不能直接这样写，应写“阻塞态 → 就绪态”。

**原因：** 打印机可用只解除了阻塞原因，P 是否运行还取决于调度。题干第 3 步只说明唤醒，没有说明 P 已获得 CPU。

**第 3 问结论：** P 进入就绪态。

**原因：** 时间片用完只使 P 暂时失去 CPU，P 仍能继续执行；阻塞态要求进程正在等待某个尚未完成的事件。

## 变式一：时间片用完和读磁盘怎样区分？

进程 A 正在运行。先发生时间片用完；A 再次被调度后执行读磁盘操作，需要等待 I/O。写出这两个事件各自触发的转换。

**结论：** 时间片用完触发“运行态 → 就绪态”；等待磁盘 I/O 触发“运行态 → 阻塞态”。

**原因：** 前者使 A 失去 CPU，但 A 仍可运行；后者使 A 在 I/O 完成前无法继续。

## 变式二：改正错误的状态链

某同学写道：“进程 B 等待的键盘输入到达后，B 从阻塞态直接进入运行态。”请改正并解释。

**结论：** 通常应改为“B 从阻塞态进入就绪态”；只有随后被调度并获得 CPU，B 才从就绪态进入运行态。

**原因：** 输入到达解除了等待条件，使 B 具备运行条件；获得 CPU 还需要调度。

## 变式三：哪条箭头通常不该画？

在基础三态图中，有人画出“就绪态 → 阻塞态”，理由是“就绪进程也可能将来申请 I/O”。这条箭头是否合适？

**结论：** 通常不合适。

**原因：** 就绪进程尚未占用 CPU，不能执行申请 I/O 等导致自身阻塞的操作。它通常先由就绪态进入运行态，再由运行态进入阻塞态。
