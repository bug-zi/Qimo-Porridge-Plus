# 已完成课程在批量任务取消后保留并交付——修复方案

## 1. 本次先解决的问题

一次请求生成多节课时，前面某节已经完整生成并保存；用户取消后续生成，已经完成的课程不能被回滚、覆盖或在界面上隐藏，必须立即交付给用户，并允许之后继续生成剩余课程。

本次只聚焦数据交付和取消后的状态语义，不先处理三节课耗时很长的模型优化，也不把任务改造成父子 Job。

## 2. 已确认的当前行为与根因

课程计划可能有多于本批数量的任务。一次 lessonLimit=3 只会从所有尚未完成的正式任务中按 day/order 取前 3 个；已有 studyGuide 的任务不会计入本批目标。因此必须区分整门计划、本批目标、本批已完成和历史已完成。当前 Job 没有持久化这四类信息，取消后无法准确告诉用户本批完成了几节。

后端已有逐节落盘路径：study_service.py 的 _write_content_lesson_preview 在 lesson_built 回调时重新读取最新 workspace，按 task id 写入完整 studyGuide 和 practiceQuestions，并立即保存。取消时 workflow 只清理当前未完成节的 checkpoint，不应删除此前已发布的小节。

真正缺失的是取消结算和结果交付：取消发生在 run_content_workflow 尚未正常返回时，approve_strategy_documents 直接重新抛出 AgentJobCancelled，worker 只把 Job 记为 cancelled，没有生成包含完成度的结果摘要。前端只能看到“已停止”，容易误以为全部内容被吞掉。

## 3. 修复目标

1. 每节完整生成并发布后即视为不可撤销的已完成内容。
2. 取消只停止当前未完成节及后续节，不回滚此前已发布内容。
3. 取消结算从最新 workspace 统计，不能依赖任务启动时旧副本。
4. Job 终态持久化本批目标、已完成、待完成、取消位置和可继续信息。
5. 刷新页面仍能恢复已完成 X 节、剩余 Y 节。
6. 再次继续时跳过已有完整 studyGuide 的课程。
7. 保持质量校验、首 token 超时、同课程互斥和显式失败策略不变。

## 4. 实施设计

### 4.1 定义本批完成标准

本批统计只以最新 workspace 中目标 task 是否存在完整 studyGuide 为准，排除 orientation，并只统计本批目标，避免把历史已完成任务误算为本批产出。建议抽取纯函数，输出 requestedLessonCount、completedLessonCount、pendingLessonCount、completedLessonIds、pendingLessonIds。

### 4.2 保存批次快照

在真正确定 selected tasks 后保存 batchTargetIds、batchTotal、batchCompletedIds、batchPendingIds、currentTaskId、currentStage 和 cancelledAt。每次 lesson_built 成功落盘后更新完成列表，更新携带 lease token，继续遵守 fencing。

若旧任务没有批次快照，取消结算时只能按最新未完成顺序做兼容推断，并标记 inferred，不能把历史课程冒充本批完成。

### 4.3 取消时结算已发布内容

取消路径必须：不删除任何已经由 lesson_built 写入 workspace 的任务；只清理当前模型产生的未完成 checkpoint；重新读取最新 workspace；根据 batchTargetIds 统计完成和待完成；写入取消结果摘要；保证迟到的 handler 返回不能把 cancelled 覆盖为 completed。

建议结果包含：cancelledByUser、partial、requestedLessonCount、completedLessonCount、pendingLessonCount、completedLessonIds、pendingLessonIds、cancelledTaskId、cancelledStage、message。

如果第一节完成、第二节正在生成后取消，结果必须是 1/3，第一节必须保留；如果第二节也完成后取消，结果必须是 2/3；如果第一节尚未完整发布，结果应为 0/3。

### 4.4 前端展示与刷新即时反映

取消终态同时使用 workspace 实际内容和 Job 结果摘要：明确显示已完成 X/Y 节，说明已完成内容已保留，显示剩余数量和继续生成入口。旧任务没有 result 时只展示兼容提示，不伪造精确批次数字。

批量生成过程中也必须实时交付已完成小节，而不是等整个 Job 结束。每节完成并由后端写入 workspace 后，前端下一次轮询或用户点击刷新都要重新读取最新 workspace；如果该 task 已有完整 studyGuide，就立即把课程卡片从“内容生成中”切换为“开始学习”，同时保留本批进度提示（例如“已完成 1/3 节”）。

刷新不能只刷新 Job 状态，也不能只依赖 Job 的最终 result：必须同时刷新 workspace/课程任务数据。前端应按 task id 合并服务端最新任务状态，不能用生成任务启动时的旧 tasks 覆盖已完成内容。正在生成的当前小节仍显示“内容生成中”；已经完成的小节独立显示“开始学习”。即使批量 Job 仍为 running，已完成小节也必须可点击进入学习。

验收时要验证：第一节完成、第二节生成中时点击刷新，第一节显示“开始学习”，第二节仍显示“内容生成中”；取消后再次刷新，第一节仍显示“开始学习”，并显示剩余课程可继续生成。

## 5. 影响范围

## 6. 测试与验收

后端测试：目标 3 节，第一节完成后取消，workspace 保留第一节且 result 为 1/3；第二节完成后取消，保留前两节且 result 为 2/3；第一节未完成取消则为 0/3；迟到响应不能覆盖 cancelled；继续生成跳过已完成课程；历史已完成课程不计入本批；刷新后状态一致。

前端真实交互验收：第一节完成、第二节仍在生成时点击刷新，第一节卡片必须从“内容生成中”变为“开始学习”，且可以进入学习；第二节仍显示“内容生成中”。取消后再次刷新，第一节及其他已完成小节仍可学习，未完成小节仍可继续生成。
