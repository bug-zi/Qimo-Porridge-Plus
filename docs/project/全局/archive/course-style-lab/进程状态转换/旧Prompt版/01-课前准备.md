# 进程状态转换｜课前准备

## 关键词

**运行态、就绪态、阻塞态、CPU、调度、等待事件、唤醒**

## 从打印任务看三个状态

想象学校机房里有一个进程 P 正在处理打印任务。P 有时占用 CPU 执行，有时已经可以执行却还在排队等 CPU，有时又必须等打印机可用才能继续。三种处境分别对应运行态、就绪态和阻塞态。

### 先思考这几个问题

1. P 正在 CPU 上执行时处于什么状态？
2. P 已经具备执行条件，只等 CPU 时，与等待打印机时有什么区别？
3. 打印机可用后，P 为什么通常还要先排队等待调度？
4. 时间片用完与等待打印机，会让 P 进入同一种状态吗？

## 三个状态怎样对应这个场景？

**运行态**：进程正在占用 CPU 执行。场景中的 P 获得 CPU 并处理打印任务时处于运行态。

**就绪态**：进程已经具备运行条件，只差 CPU。场景中的 P 可以继续处理任务，但 CPU 正由其他进程占用时，P 在就绪队列中等待调度。

**阻塞态**：进程正在等待某个事件，暂时不具备运行条件。场景中的 P 等待打印机可用时，即使立刻给它 CPU，也无法继续推进。

**CPU**：执行进程指令的处理机资源。进程是否正在占用 CPU，是识别运行态的第一条判断线索。

**调度**：从具备运行条件的进程中选择一个并分配 CPU。就绪进程被选中后才能进入运行态。

**等待事件**：进程继续执行前必须满足的条件，例如 I/O 完成或所需资源可用。正在运行的进程遇到未满足的等待条件，会进入阻塞态。

**唤醒**：等待事件完成后，系统让阻塞进程重新具备运行条件。进程被唤醒后通常先进入就绪态，等待调度。
