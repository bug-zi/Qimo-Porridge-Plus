# 进程状态转换｜自测

## 一、单项选择题

### 1. 某进程已经具备运行条件，正在等待系统分配 CPU。该进程处于（ ）。

A. 运行态  
B. 就绪态  
C. 阻塞态  
D. 无法判断

### 2. 正在运行的进程执行读磁盘操作，并且必须等待磁盘 I/O 完成。其直接状态转换是（ ）。

A. 运行态 → 就绪态  
B. 就绪态 → 运行态  
C. 运行态 → 阻塞态  
D. 阻塞态 → 就绪态

### 3. 时间片用完后，当前进程仍具备继续执行条件。其直接状态转换是（ ）。

A. 运行态 → 就绪态  
B. 运行态 → 阻塞态  
C. 就绪态 → 阻塞态  
D. 阻塞态 → 运行态

### 4. 阻塞进程等待的 I/O 已完成，题干没有说明该进程立即获得 CPU。此时该进程通常进入（ ）。

A. 运行态  
B. 就绪态  
C. 仍保持阻塞态  
D. 由就绪态直接进入阻塞态

### 5. 关于基础三态模型的直接转换，下列说法正确的是（ ）。

A. 就绪进程等待 CPU，所以它会直接进入阻塞态  
B. 阻塞原因解除后，进程必定直接进入运行态  
C. 运行进程被高优先级进程抢占后，通常进入就绪态  
D. 就绪进程无须调度即可进入运行态

## 二、场景简答题

### 6. 抢占与等待资源

进程 P 正在运行。事件一：更高优先级进程到达，P 被抢占；事件二：P 后来再次运行并申请某资源，但资源暂不可用。分别写出两个事件触发的状态转换，并说明判断依据。

### 7. 从阻塞恢复到运行

进程 Q 因等待键盘输入处于阻塞态。键盘输入到达后，Q 随后被调度程序选中并获得 CPU。写出 Q 的完整状态变化链，并解释为什么要写出中间状态。

## 三、答案与解析

### 1. B

**结论：** 该进程处于就绪态。

**原因：** 它已经具备运行条件，只差 CPU；等待 CPU 属于等待调度。

### 2. C

**结论：** 发生“运行态 → 阻塞态”。

**原因：** 进程必须等待 I/O 完成，在事件完成前无法继续执行。

### 3. A

**结论：** 发生“运行态 → 就绪态”。

**原因：** 进程失去 CPU 后仍可继续运行，只需等待再次调度。

### 4. B

**结论：** 进程通常进入就绪态。

**原因：** I/O 完成解除了阻塞原因，但没有保证进程已经获得 CPU。

### 5. C

**结论：** 被抢占的运行进程通常进入就绪态。

**原因：** 它只是失去 CPU，仍具备运行条件。A 混淆了等待 CPU 与等待事件；B 跳过了调度；D 忽略了获得 CPU 的必要条件。

### 6. 参考答案

**结论：** 事件一触发“运行态 → 就绪态”；事件二触发“运行态 → 阻塞态”。

**原因：** 被抢占后，P 仍具备运行条件，只是暂时失去 CPU；申请的资源不可用时，P 必须等待资源可用，即使获得 CPU 也不能继续推进。

### 7. 参考答案

**结论：** Q 的状态变化链是“阻塞态 → 就绪态 → 运行态”。

**原因：** 键盘输入到达先解除等待条件，使 Q 由阻塞态进入就绪态；调度程序随后选中 Q 并分配 CPU，Q 才由就绪态进入运行态。中间的就绪态区分了“已经具备运行条件”和“已经获得 CPU”两个时刻。
