# 午间接单前，先认清三种处境

## 本节关键词

- **运行态**
- **就绪态**
- **阻塞态**
- **调度与获得 CPU**
- **时间片用完或被抢占**
- **等待事件与事件完成**

## 奶茶店的午间队列

午休铃响后，校园奶茶店的订单迅速增加。店里只有一台封口机，我们把它对应为 CPU，把每张待处理订单对应为一个进程。

店员小程先看到三张订单：一张正在封口机上处理；一张材料齐全，排队等封口机；还有一张缺少刚煮好的珍珠，即使封口机现在空出来也无法继续。三张订单都没有消失，却处于三种不同处境。

这个映射只帮助我们观察条件：占用封口机对应占用 CPU；材料齐全、只等封口机对应具备运行条件但未占 CPU；缺少珍珠、必须等事件发生对应暂时不具备运行条件。技术判断仍以进程是否占用 CPU、是否具备运行条件为准。

带着场景先想四个问题：

1. 没有占用 CPU 的进程都属于阻塞态吗？
2. 正在运行的进程时间片用完后，为什么通常进入就绪态？
3. 等待的 I/O 完成后，进程为什么通常先进入就绪态？
4. 三态图上应画出哪四条直接转换，又有哪两条通常不能直接转换？

## 三个状态各自说明什么

### 运行态：订单正在使用封口机

**运行态**表示进程正在占用 CPU 执行。故事中，正在封口机上处理的订单对应运行态。判断重点是“当前正在占用 CPU”。

### 就绪态：条件齐全，只等封口机

**就绪态**表示进程已经具备运行条件，但尚未占有 CPU，只等待调度。故事中，材料齐全并排队等封口机的订单对应就绪态。等待 CPU 属于就绪态，不属于等待外部事件的阻塞态。

### 阻塞态：缺少条件，空出封口机也做不了

**阻塞态**表示进程暂时不具备继续运行的条件，正在等待 I/O 完成、资源可用、信号量条件满足或消息到达等事件。故事中，缺少珍珠的订单对应阻塞态。即使此时把 CPU 分给它，它也不能立即继续执行。

## 三类触发词先建立对应

- 看到“被调度、被选中、获得 CPU”，关注**就绪态到运行态**。
- 看到“时间片用完、被更高优先级进程抢占”，关注进程失去 CPU 后是否仍能执行。
- 看到“等待 I/O、等待资源”或“事件完成、被唤醒”，关注运行条件是否从具备变为不具备，或从不具备恢复为具备。

午间订单继续流转时，小程需要决定每次变化应沿哪一条箭头移动。判断箭头前，我们还缺少一个核心答案：**进程离开 CPU 后，怎样依据“还能不能立即继续执行”区分就绪态与阻塞态？**
