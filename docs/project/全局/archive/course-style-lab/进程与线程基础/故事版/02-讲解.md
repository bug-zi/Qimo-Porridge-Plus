# 进程与线程基础｜讲解

> 接着浏览器里的下载事件，理清进程与线程的关系，再理解 PCB、资源共享和切换开销。

## 进程搭环境，线程做事情

上一节结束时，小林的浏览器仍在下载课程文件。她已经知道：浏览器启动后会形成进程，界面响应、网络加载和页面渲染等任务可以交给不同线程。

现在把两者的分工说准确：浏览器运行需要地址空间、内存、文件等资源，也需要有人一步步执行界面响应和网络加载等任务。**进程负责把这次运行需要的资源组织起来，线程负责在这个环境里执行具体任务。**

```text
一个正在运行的应用
└─ 进程：提供并组织资源环境
   ├─ 线程 1：推进一项任务
   ├─ 线程 2：推进另一项任务
   └─ 线程 3：推进其他任务
```

一个进程至少包含一条线程，也可以包含多条线程。它们共用进程提供的资源环境，同时各自记录执行进度。

为了让这个结论站稳，小林决定从头追一遍：进程究竟是怎么来的？

## 从磁盘文件到一次运行

磁盘里的应用程序是一组静态的指令和数据。操作系统加载程序、分配资源并开始执行后，才形成一次实际的运行活动，也就是进程。

因此，**程序是静态内容，进程是程序的一次运行**。同一个程序可以启动多次，每次运行都可以形成一个进程。它们使用相同的程序代码，却各自拥有运行状态和资源环境。

例如，同一个代码编辑器被启动两次，系统创建两个不同 PID 和独立地址空间，这就是两个进程。

进程比程序多了运行状态和资源环境。操作系统要同时管理它们，就必须记住这些动态信息。

## PCB 让暂停后的进程接着运行

假设进程 P 正在使用 CPU，随后系统让 P 暂停，把 CPU 交给其他任务。等 P 再次运行时，它必须从暂停处继续，而不是从头再来。

为此，操作系统给每个进程维护一份 **PCB（进程控制块）**。

| 操作系统要掌握的内容 | PCB 中的相关信息 |
| --- | --- |
| 管理的是哪个进程 | 进程标识 |
| 进程当前处于什么状态 | 进程状态、调度信息 |
| 进程执行到了哪里 | 程序计数器、寄存器现场 |
| 进程正在使用哪些资源 | 内存、进程级打开文件资源等信息 |

进程暂停时，系统保存必要现场；进程再次获得 CPU 时，系统依据保存的信息恢复执行。操作系统也依靠这些信息识别进程、安排调度并回收资源。

所以教材才会概括：**PCB 是进程存在的唯一标志。** 这里强调的是操作系统依靠 PCB 识别和管理进程；PCB 的具体字段会随系统实现变化。

## 一个进程为什么需要多条线程

小林看着浏览器：它要响应操作、加载网页资源、渲染页面、播放音视频。如果所有工作只有一条执行线，其中一项任务等待时，其他任务也可能被拖住。

线程让一个进程内部拥有多条执行线。不同线程可以分别推进界面响应、网络加载和页面渲染等任务。

这时，分工可以落回两个标准结论：

- **进程通常是资源分配的基本单位**，提供地址空间和进程级资源；
- **线程通常是 CPU 调度的基本单位**，在进程提供的环境中执行任务。

也就是：**进程组织资源，线程推进执行。**

多条线程要协作，所以会共用进程资源；它们又在执行不同任务，因此还要分别保存自己的执行进度。

## 下载进度为何能被界面直接读到

同一进程内的线程处在共同的资源环境中，因此通常共享：

- 地址空间和程序代码；
- 全局变量、静态数据和堆；
- 进程级打开文件资源。

下载线程把最新进度写入共享数据后，界面线程可以直接读取并刷新进度条。共享地址空间让协作更加直接。

可如果多条线程同时读写一份数据，执行步骤交错，就可能发生更新丢失或数据不一致。后续的同步互斥机制正是用来解决这类问题的。

## 共用资源，不等于共用执行进度

小林差点把“共享”理解成“什么都共用”，但每条线程执行到哪里、正在进行哪次函数调用，属于它自己的执行过程。

因此，每条线程通常分别保存：

- 程序计数器：记录下一条要执行的指令；
- CPU 寄存器现场：记录当前计算状态；
- 线程栈：记录函数调用、局部变量和返回位置；
- 线程 ID 和运行状态：用于识别和调度线程。

判断时抓住一点：属于整个进程的资源，通常由线程共享；描述某条线程执行进度的内容，需要分别保存。

这种“资源共享、现场独立”的关系，也解释了线程切换为什么通常更轻。

## 两种切换，范围并不一样

CPU 更换执行对象时，需要保存当前现场，再恢复下一个执行对象的现场。

跨进程切换时，前后两个进程通常拥有不同地址空间。系统除了处理程序计数器和寄存器，还可能更换内存管理上下文，并处理更多进程级信息。

同一进程内线程切换时，地址空间和进程级资源继续沿用，系统重点切换线程自己的程序计数器、寄存器和栈。

因此，**同一进程内线程切换的开销通常小于跨进程切换**。线程切换仍需保存和恢复执行现场，所以依然有开销；具体成本会受到操作系统和硬件实现影响。

## 小林记下的三步判断法

下载快结束时，小林把这节内容压成三个做题动作：

1. **先找进程。** 哪个程序被启动了，系统为这次运行组织了哪些资源；要识别和管理这次运行，再看 PCB 记录的信息。
2. **再找线程。** 进程里有哪些任务分别推进；地址空间、全局数据等进程资源通常共享，程序计数器、寄存器和栈等执行信息由各线程分别保存。
3. **最后看切换范围。** 两条线程属于同一进程时，可以继续使用原地址空间；切换跨越进程时，还可能更换内存管理上下文。
