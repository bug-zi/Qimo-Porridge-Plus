# 进程与线程基础｜课前准备

> 版本：V0.4（生活化表达）  
> 本节关键词：程序、进程、PCB、线程、资源共享、上下文切换。

## 从我们每天都在用的浏览器说起

你可能有过这种经历：浏览器里开着十几个网页，视频正在播放，文件也在下载，这时候你还能继续点开新的页面。屏幕上看起来只是一个浏览器，背后其实有不少任务在同时往前跑。

站在操作系统的角度，可以先把这个场景画成这样：

```text
磁盘里的浏览器文件
    ↓ 双击启动
浏览器进程
    ├─ 界面线程：负责响应你的点击
    ├─ 网络线程：负责接收网页和下载数据
    └─ 渲染线程：负责把内容显示到页面上
```

先思考几个很实际的问题：

- 浏览器安静地躺在磁盘里，和它真正运行起来，有什么区别？
- 浏览器占用的内存、打开的文件和网络连接，由谁统一管理？
- 下载文件时页面还能正常操作，这些任务是怎么一起推进的？
- CPU 执行到一半去处理别的任务，回来后怎么知道刚才做到哪了？

这几个问题正好对应下面要认识的关键词。

## 程序：还没跑起来的那份代码

**程序**是保存在磁盘等介质上的指令和数据。

我们可以把它想成一份菜谱：步骤都写好了，但厨师还没动手，厨房里也没有正在进行的烹饪过程。磁盘里的浏览器可执行文件就是程序，它说明浏览器可以做什么，此时还没有自己的运行状态。

## 进程：程序真正跑起来后的这一趟

双击浏览器图标后，操作系统把程序加载起来，给它安排地址空间、内存和文件等资源。此时产生的一次运行，就是**进程**。

程序和进程的关系，有点像“游戏安装包”和“这一局正在进行的游戏”：安装包可以反复启动，每启动一次，都可能形成一个新的运行实例。同一款编辑器启动两次时，系统也可能创建两个进程；它们使用相同的程序代码，却各自保留运行状态和资源环境。

## PCB：操作系统给进程建的档案

电脑同时运行很多进程，操作系统不能靠“我好像见过它”来管理。每个进程都需要一份可以查、可以改的管理记录，这就是 **PCB（进程控制块）**。

PCB 通常记录：

- 这是哪个进程：进程标识；
- 它现在是什么状态：进程状态和调度信息；
- 它刚才执行到哪里：程序计数器和寄存器现场；
- 它正在使用什么：内存、进程级打开文件资源等信息。

进程被暂停时，操作系统把必要信息保存好；它再次获得 CPU 时，再根据这些信息从原来的位置继续。这个过程很像游戏存档：先记住进度，之后才能接着玩。

教材常说“PCB 是进程存在的唯一标志”，强调的就是操作系统通过这份档案识别和管理进程。

## 线程：进程里的任务执行线

一个浏览器进程里往往不止一件事：既要响应点击，又要加载网页，还可能在后台下载文件。如果所有任务排成一条长队，下载稍微卡一下，整个浏览器都得跟着干等。

**线程**就是进程内部的一条执行线。一个进程至少有一条线程，也可以安排多条线程分别推进不同任务。

放回浏览器场景中，界面响应、网络加载和页面渲染就是三类不同任务，可以由不同线程各自推进。这样，即使网络加载暂时在等待，界面线程仍有机会继续响应你的操作。

## 资源共享：同一进程里的线程可以共用哪些资源

这些线程都属于同一个进程，因此通常可以共享：

- 地址空间和程序代码；
- 全局变量、静态数据和堆；
- 进程级打开文件资源。

比如下载线程更新了进度数据，界面线程可以直接读取这份数据并刷新进度条，不需要为两条线程各准备一份副本。

方便也有代价。两条线程如果同时修改同一份数据，就像两个人同时改一张订单，最后可能谁也说不清哪一版才对。后面学到同步互斥时，我们会专门处理这个问题。

## 上下文切换：CPU 换人干活前要先记住进度

CPU 不会永远只执行一个任务。它从当前任务切换到另一个任务前，需要先保存当前任务的运行信息，再恢复下一个任务的运行信息，这就是**上下文切换**。

可以把它想成你写作业时临时去接电话：离开前最好记住题目做到哪一步，回来后才能接着写。CPU 切换任务也是同样的道理。

同一进程内的线程共享地址空间，切换时通常主要处理线程自己的程序计数器、寄存器和栈。跨进程切换还可能更换地址空间和内存管理上下文，所以同进程线程切换通常更轻。

不过“更轻”不等于没有开销。只要换了执行对象，保存和恢复现场这部分工作就跑不掉。

## 这些词先混个脸熟，别急着背

到这里，我们只需要先知道这些词大概在说什么。真正容易让人绕晕的，是进程和线程为什么要同时存在：一个负责什么，另一个又负责什么，它们在同一个应用里怎么配合。
