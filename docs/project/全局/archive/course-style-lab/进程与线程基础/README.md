# 进程与线程基础｜课程风格共创区

这里用于在 DSH 中完成课程样式的 **0→80 共创**。当前四份 V0.1 样稿均为实验文档，不会直接修改网站中的正式课程。

## 样稿入口

1. [课前准备](./01-课前准备.md)：用场景和关键词建立进入讲解前所需的术语基础。
2. [讲解](./02-讲解.md)：确定老师如何把知识连贯地讲出来。
3. [例题](./03-例题.md)：确定例题数量、递进顺序、分析深度与答案结构。
4. [自测](./04-自测.md)：确定题型组合、覆盖度、解析方式与自评标准。

## 推荐审阅顺序

### 第一步：只看讲解

先判断整体讲述是否符合预期：

- 开头是否进入主题太慢；
- 概念出现顺序是否自然；
- 解释是否像老师讲课；
- 小标题是否过多或过少；
- 哪些段落有明显“AI 味”；
- 哪些句子值得保留为正例。

### 第二步：核对课前准备

检查：

- 是否有该讲却没讲的内容；
- 是否混入了本节范围之外的内容；
- “常见考法”和“易错点”是否有用；
- 表格、口诀和总结是否符合阅读习惯。

### 第三步：看例题

重点选择例题编排方向：

- 多道独立递进题；
- 一个统一场景下的连续问题；
- 一个主例题加若干独立变式。

同时检查“分析—解答—结论”是否重复，答案应该展开到什么程度。

### 第四步：做自测

不看答案完成自测，并记录：

- 题目是否真正检验理解；
- 选项是否过于容易排除；
- 判断与简答是否有必要；
- 答案解析是否太长；
- 自评标准是否有实际帮助。

## 反馈方式

可以直接修改 Markdown，也可以在 DSH 中自然描述。例如：

> 讲解第 2 节像百科，改成先用“进程暂停后怎么继续”引出 PCB。  
> 保留“进程组织资源，线程推进执行”这句话。  
> 删除每节结尾的重复总结。  
> 例题改成一个主场景串联，再补两道变式。  
> 自测选项太容易，错误项要来自真实概念混淆。

## 后续提炼 80 分 Prompt 时记录的维度

用户确认样稿后，再从最终版本中提炼：

1. **课程宏观结构**：考点、讲解、例题、自测之间的职责和顺序；
2. **讲述路径**：从场景、问题、定义、原理到边界的组织方式；
3. **语言规则**：句长、语气、术语密度、小标题和列表偏好；
4. **例题规则**：题量、场景连续性、分析深度、答案结构；
5. **自测规则**：题型比例、难度、干扰项来源和解析长度；
6. **明确禁用项**：不喜欢的句型、套话、冗余模块和虚假考试导向；
7. **正反例**：从用户保留和删除的原文中选择最具代表性的样例。
