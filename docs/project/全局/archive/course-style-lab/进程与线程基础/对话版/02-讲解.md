# 进程与线程基础｜讲解

> 版本：V0.4（对话式教学）  
> 先看清进程与线程的关系，再顺着这条主线理解 PCB、资源共享和切换开销。

## 先把进程和线程的关系理清

**老师：** 上一节我们用浏览器开了个头：浏览器启动后形成进程，界面响应、网络加载和页面渲染可以交给不同线程。为什么既需要进程，又需要线程？

**学生：** 浏览器运行要有地址空间、内存、文件等资源，也要有人把各项任务一步步执行下去。

**老师：** 正好对应二者的分工：**进程负责把这次运行需要的资源组织起来，线程负责在这个环境里执行具体任务。** 我们可以先这样理解：

```text
一个正在运行的应用
└─ 进程：提供并组织资源环境
   ├─ 线程 1：推进一项任务
   ├─ 线程 2：推进另一项任务
   └─ 线程 3：推进其他任务
```

**学生：** 一个进程至少包含一条线程，也可以包含多条。它们共用进程提供的资源环境，同时各自记录执行进度。

**老师：** 对。不过要弄清分工，我们先从进程是怎么来的讲起。

## 进程从哪里来

**老师：** 磁盘里的应用程序已经是进程了吗？

**学生：** 不是。它只是一组静态的指令和数据。操作系统加载程序、分配资源并开始执行后，才形成一次实际的运行活动，也就是进程。

**老师：** 所以，**程序是静态内容，进程是程序的一次运行**。同一个程序启动多次，会怎样？

**学生：** 每次运行都可以形成一个进程。它们使用相同的程序代码，却各自拥有运行状态和资源环境。

**老师：** 比如系统把同一个代码编辑器启动两次，创建两个不同 PID 和独立地址空间，这就是两个进程。进程比程序多出了运行状态和资源环境，而操作系统要同时管理多个进程，就必须记录这些动态信息。

## 操作系统怎样管理一个进程

**老师：** 假设进程 P 正在使用 CPU，系统随后让 P 暂停，把 CPU 交给其他任务。P 再次运行时应该从哪里开始？

**学生：** 应该从暂停的位置继续，而不是重新开始。

**老师：** 因此，操作系统给每个进程维护一份管理记录，叫 **PCB（进程控制块）**：

| 操作系统要掌握的内容 | PCB 中的相关信息 |
| --- | --- |
| 管理的是哪个进程 | 进程标识 |
| 进程当前处于什么状态 | 进程状态、调度信息 |
| 进程执行到了哪里 | 程序计数器、寄存器现场 |
| 进程正在使用哪些资源 | 内存、进程级打开文件资源等信息 |

**学生：** 进程暂停时保存必要现场，再次获得 CPU 时依据记录恢复。系统还用这些信息识别进程、安排调度并回收资源。

**老师：** 对。教材把这种关系概括为：**PCB 是进程存在的唯一标志。** 重点是操作系统依靠 PCB 识别和管理进程；PCB 的具体字段会随系统实现变化。

**学生：** 有了 PCB，进程能管理了。但应用内部如果同时有多项工作，一条执行线还是很难兼顾。

## 为什么一个进程里还需要线程

**老师：** 仍以浏览器为例。如果响应操作、加载资源、渲染页面和播放音视频全都沿一条执行线依次进行，会有什么问题？

**学生：** 其中一项任务等待时，其他任务也可能被拖住。

**老师：** 线程让一个进程内部拥有多条执行线，不同线程可以分别推进这些任务。这样，进程与线程的分工就清楚了：

- **进程通常是资源分配的基本单位**，提供地址空间和进程级资源；
- **线程通常是 CPU 调度的基本单位**，在进程提供的环境中执行任务。

**学生：** 也就是：**进程组织资源，线程推进执行。**

**老师：** 对。多条线程要协作，所以会共用进程资源；它们又在执行不同任务，所以还要分别保存自己的执行进度。

## 同一进程中的线程怎样共享资源

**老师：** 同一进程内的线程通常共享哪些内容？

**学生：** 地址空间和程序代码，全局变量、静态数据和堆，以及进程级打开文件资源。

**老师：** 比如下载线程把最新进度写入共享数据，界面线程可以直接读取并刷新进度条。共享地址空间让协作更直接。不过多条线程同时读写同一份数据时呢？

**学生：** 如果执行步骤交错，就可能更新丢失或数据不一致，后续要靠同步互斥机制解决。

## 共享资源后，线程为什么还要有自己的现场

**老师：** 有同学会问：“既然资源共享，程序计数器和栈也共用一份不行吗？”你怎么看？

**学生：** 不行。每条线程执行到哪里、正在进行哪次函数调用，都属于它自己的执行过程。

**老师：** 因此，每条线程通常分别保存：

- 程序计数器：记录下一条要执行的指令；
- CPU 寄存器现场：记录当前计算状态；
- 线程栈：记录函数调用、局部变量和返回位置；
- 线程 ID 和运行状态：用于识别和调度线程。

**学生：** 判断时可以抓住一点：属于整个进程的资源，通常由线程共享；描述某条线程执行进度的内容，需要分别保存。

**老师：** 很好。资源共享、现场独立，也解释了线程切换为什么通常更轻。

## 为什么同进程线程切换通常更轻

**老师：** CPU 更换执行对象时，都要先保存当前现场，再恢复下一个执行对象的现场。跨进程切换和同进程线程切换，差别在哪里？

**学生：** 跨进程切换时，前后进程通常拥有不同地址空间。系统除了处理程序计数器和寄存器，还可能更换内存管理上下文，并处理更多进程级信息。

**老师：** 那同一进程内线程切换呢？

**学生：** 地址空间和进程级资源继续沿用，系统重点切换线程自己的程序计数器、寄存器和栈。

**老师：** 因此，**同一进程内线程切换的开销通常小于跨进程切换**。但线程切换仍要保存和恢复现场，所以仍有开销；具体成本也会受操作系统和硬件实现影响。

## 遇到运行场景，按这三步判断

**老师：** 现在把这一节收束成三个判断动作：

1. **先找进程。** 哪个程序被启动了，系统为这次运行组织了哪些资源；需要识别和管理这次运行时，再看 PCB 记录的信息。
2. **再找线程。** 进程里有哪些任务在分别推进；地址空间、全局数据等进程资源通常共享，程序计数器、寄存器和栈等执行信息由各线程分别保存。
3. **最后看切换范围。** 两条线程属于同一进程时，可以继续使用原来的地址空间；切换跨越进程时，还可能更换内存管理上下文。

**学生：** 下一步就是把这三步放进题目里练习。

**老师：** 对。下一节换成下载器场景，把程序、进程、PCB、资源共享和切换开销放在一起分析，我们再熟悉一遍这三步判断方法。
