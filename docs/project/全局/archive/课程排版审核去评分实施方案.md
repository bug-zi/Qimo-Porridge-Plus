# 课程排版审核去评分实施方案

## 现状分析

当前课程排版功能由 `backend/app/agents/readability_review.py` 提供结构、段落、列表、公式上下文和故事版流程审核。审核结果同时包含审核状态、问题列表和评分字段；单课与课程汇总均计算 score，并以分数阈值辅助通过判定。

课程生成流程会把排版审核结果写入每个课节和课程工作区；前端主线页提供“审核课程排版”入口和汇总卡片，学习页还显示“排版易读性 X 分”。Demo 数据、TypeScript 类型和后端测试也依赖评分字段。

## 需求理解

课程排版仍然需要审核，但审核是定性审核，不再评分。保留手动触发、单课/全课程状态、问题建议、已生成/待生成统计和审核时间；删除单课及汇总数值评分、评分文案、评分阈值判定，以及相关 API 返回、类型、Demo 和测试断言中的排版评分字段。练习题分值、模拟卷得分、目标分数和预估分数不在本次范围内。

## 影响范围

1. 后端 `readability_review.py`：移除 score 计算与返回；状态依据 error 级问题和审核可用性判定。
2. 检查 `content_workflow.py`、`study_service.py` 的审核写入链路，仅保留非评分信息。
3. 更新 `test_readability_review.py` 及相关契约测试。
4. 删除前端审核类型中的 score 字段，确认 API 透传契约。
5. 主线审核卡片和学习页保留定性结论、统计及问题，移除数值评分与“暂不计算评分”文案。
6. 清理 Demo 审核数据和仅用于排版评分展示的逻辑/样式引用。
7. 更新开发看板并执行验证三件套。

## 风险与兼容性

历史 workspace 中的旧 score 字段不做破坏性迁移，读取时忽略且前端不展示；新审核结果不再写入。passed 表示没有 error 级排版问题。练习和模拟卷 score 必须保留。生产构建若复现既有 Windows 原生退出问题需单独记录。

## 测试及验收方式

后端执行 `backend/.venv/Scripts/python.exe -m pytest tests -q`；前端执行 `npx tsc -b` 和 `npm run build`。全局搜索确认排版审核相关返回、类型、Demo 和界面不再计算或展示分数。功能验收：仍可审核课程排版，显示通过/需要关注、问题、统计和时间，不显示任何排版分数。

## 回滚方式

仅回退本次代码和测试改动，不修改或清空用户课程数据；不执行 Git 提交。
