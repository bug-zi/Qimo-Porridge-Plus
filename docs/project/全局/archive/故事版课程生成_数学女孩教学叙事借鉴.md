# 故事版课程生成：基于《数学女孩》的教学叙事改进建议

> 目的：提炼可迁移的教学叙事方法，不复刻作品原句、角色、情节或独特表达。

## 一、核心判断

《数学女孩》最值得借鉴的不是校园故事外壳，而是把思考过程本身写成事件：具体情境触发问题；学习者先给直觉答案或典型误答；角色追问遗漏的对象、条件和边界；通过代值、反例、图形、符号变形或定义检验；学习者修订表达；从具体上升到一般；最后落到精确定义、公式、条件和结论；新结论再打开更深的问题。

## 二、可迁移机制

### 1. 微场景触发，而非长篇铺垫
开场尽快出现一个可推理的问题。场景只需要一个地点、一个动作、一个对象；情节必须负责制造问题、展示条件变化、暴露误区或推动应用。

### 2. 角色差异承担脚手架功能
不要只设置老师和学生。可为角色增加认知职责：intuition（快速猜想）、checker（查条件和反例）、formalizer（落回定义和符号）、novice（提出术语疑问）、connector（连接前课）。每课通常 2 至 3 个角色即可，角色可以答错，也可以纠正讲解者。

### 3. 把误解写成生产力
高质量误答往往只错一个关键点，例如漏掉另一个解、忘记适用条件、把“一个位置”说成“最小位置”。误答不能被一句“正确答案是……”覆盖，必须用具体计算、反例、边界或定义展开完成诊断，并让原回答者重新表述。

### 4. 推理显微化
把隐性思考动作写出来：观察、猜想、代入具体值、比较、找反例、核对条件、改进表示、推广、形式化、反思、迁移。explanation beat 不应只按数量规划，而应按必要的推理动作规划。

### 5. 直觉与形式反复往返
生活语言负责让人进入问题，随后必须落回标准术语。每个类比都要紧邻准确映射与至少一个边界；类比不能替代定义、计算或证明。

### 6. 定期进行数学清场
连续对话后暂停叙事，集中展示已知条件、标准定义、公式或推理链、结论、适用边界和最小反例。建议在 UI 中渲染为独立的板书卡，避免公式淹没在对白中。

### 7. 把问题承接升级为问题账本
incomingQuestion 和 outgoingQuestion 只能保证形式衔接。建议增加问题状态：opened、partially_resolved、boundary_pending、generalized、proved、transferred；后续课程重新调用尚未解决的问题，并更新其状态。

### 8. 情绪和动作只做节奏标点
停顿、惊讶和轻微动作可以标记发现或犹豫，但每个 beat 最多保留一个有认知功能的动作，删除纯装饰、暧昧或与学习无关的描写。

## 三、当前项目的优点与风险

已有优点：storyContext、conceptMappings、跨课问题、四段学习流程、主故事例题加独立变式、条件边界字段、结构校验和可读性审核都已具备良好骨架。

主要风险：固定四段可能造成分页割裂；3 至 8 个 beats 可能诱发凑数量；单一连续故事可能让情节压过认知；实名和动作要求尚未保证角色有不同思考功能；现有审核主要检查字段和篇幅，难以识别误答是否由证据纠正；变式可能只换数字或换皮；跨课问句尚无解决轨迹。

## 四、建议的兼容扩展字段

在不破坏现有结构的前提下增加可选字段：characterProfiles（name、cognitiveRole、known、misconceptions）、openQuestions（id、question、status、resolvedBy、remainingBoundary）、reasoningMove、misconception、evidence、revision、mathPanel（conditions、conclusion、boundary）。旧的 characters 字符串数组继续保留，由规范化层兼容新旧格式。

## 五、Prompt 调整优先级

MUST：知识准确；出现“初始理解→检验→修订→形式化/迁移”的认知链；误区由证据纠正；类比落回术语并说明边界；过程型知识展示完整步骤；故事不替代定义、计算或证明。

SHOULD：短场景尽快触发问题；角色有稳定认知职责；每 2 至 4 个叙事回合出现一次数学清场；变式覆盖边界、反例、条件改变或陌生情境。

MAY：四段继续作为 UI 分页，但生成时先产出统一认知事件链再投影；简单概念可少于 3 个 beat，复杂证明可多于 8 个；必要时允许板书、笔记或独白打断连续对白。

## 六、教学叙事质量审核

建议在结构校验和可读性审核之外增加评分：问题驱动 10、认知变化 20、错误质量 15、形式化 20、条件边界 15、角色功能 5、迁移训练 10、叙事节制 5。硬失败项包括：故事结论与标准知识冲突；类比替代定义或证明；误答未经检验即被覆盖；变式没有改变关键条件；对话删除后知识完全不受影响；数学清场与前文不一致。

## 七、操作系统示范骨架

主题：运行态、就绪态、阻塞态。小林发现下载任务暂时不动，先说“没在运行的进程都阻塞了”；阿哲追问它是在等待外部事件，还是只是暂时没拿到 CPU；比较时间片用完与发出磁盘 I/O 请求两种情况；用反例纠正“离开运行态就等于阻塞”；板书卡写出对象、触发条件和转换；主例题逐步标注事件；变式改变 I/O 完成、抢占和信号量条件；最后留下“多个就绪进程由谁运行”的问题，承接调度算法。

## 八、实施优先级

P0：改 Prompt 和审核语义，加入认知变化链、生产性错误、数学清场、证据纠错，并把 beats 数量降为建议。
P1：增加兼容字段和问题状态。P2：增加教学叙事评分与自动重写触发。P3：UI 渲染板书卡和未解决问题轨迹。

## 九、验收标准

任选概念辨析、计算过程、抽象定义三类课程：读者能指出核心问题；能说出想法如何因证据修订；删除人物姓名仍有完整定义和步骤；删除数学内容后故事不应独立成立；变式改变决定答案的条件；自测脱离故事仍能作答；下一课真正接住未完问题。

一句话总结：借鉴《数学女孩》的最佳方式，不是让课程更像小说，而是让“猜想、犯错、检验、修订、形式化”成为看得见的故事。
