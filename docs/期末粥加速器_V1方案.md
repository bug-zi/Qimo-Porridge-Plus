# 期末粥加速器 V1 方案（个人本地版）

> 更新日期：2026-08-28
> 当前执行口径：**先把个人版的本地学习闭环做扎实，再考虑校园版、企业级和服务器部署。**
> 本文已按当前仓库的实际实现重新整理，不再把“云部署、多用户运营、课程广场、管理后台”列为近期目标。

## 1. 当前产品定位

“期末粥加速器”是一款面向大学生期末冲刺的 **AI 学习工作台**。用户在 Windows 本机导入课程资料，由系统辅助完成资料解析、课程画像、复习计划、课程内容生成、练习与模拟、错题和笔记沉淀，并通过 AI 伴学持续调整复习策略。

当前版本定位为：

- 个人使用优先，而不是面向学校或企业交付。
- 数据、课程文件、配置和运行服务均保存在本机。
- FastAPI 后端与 React 前端均在本机启动，通过浏览器访问。
- 模型可调用用户自行配置的 OpenAI 兼容 API；除必要模型请求外，不主动上传本地数据。
- 已实现的账号与数据隔离代码继续保留，但当前只作为本地身份门和未来扩展基础，不继续投入校园多用户运营能力。

一句话目标：**让一个学生在本机完成“导入资料 → 生成可学课程 → 按计划学习 → 练习复盘”的完整闭环。**

## 2. 当前阶段原则

### 2.1 现在优先做

1. 提高本地运行稳定性，避免生成任务卡死、失败后无从恢复。
2. 提高资料解析、复习总计划和课程正文的质量。
3. 打磨个人真实学习流程，减少空页面、假数据和断裂入口。
4. 做好本地数据可恢复性，包括归档、版本、备份与错误提示。
5. 控制模型调用次数、Token 消耗和失败重试成本。
6. 用真实课程进行端到端验收，而不是只追求功能数量。

### 2.2 现在明确不做

- 公网服务器部署、域名、HTTPS、反向代理和云数据库。
- 课程广场、模板审核、公开分享和一键安装。
- 管理后台、管理员角色、封禁、运营统计和商业化支付。
- 企业级权限系统、组织/班级、多租户运营和高并发架构。
- Kubernetes、分布式任务队列、对象存储和多 worker 部署。
- 为移动端单独开发完整编辑体验。

以上事项不是永久删除，而是进入“本地个人版基本成熟后再评估”的远期池。

## 3. 目标用户与主要场景

目标用户是期末前需要集中复习多门课程、希望主要依赖自己资料进行速成学习的大学生。

建议主流程：

1. 在本机启动后端与前端并登录本地账号。
2. 新建课程，填写考试日期、目标分数、每日时间及补充要求。
3. 导入 PPT/PPTX、PDF、Word、Excel、Markdown、图片等资料。
4. 检查资料是否可被 AI 读取，必要时处理 OCR 或解析失败提示。
5. 生成课程画像、复习总计划与课程生成 Prompt。
6. 选择标准版、对话版或故事版课程风格。
7. 先增量生成一课并检查质量，满意后继续生成，避免一次性浪费大量 Token。
8. 按复习主线学习，通过练习、模拟卷、错题本和笔记持续复盘。
9. 使用 AI 伴学答疑、调整任务或生成待确认的计划提案。
10. 定期备份本地数据库、课程目录和模型配置。

## 4. 当前已具备的能力

以下内容来自当前代码、测试和最近提交，不等同于“全部已经达到最终质量”。

### 4.1 本地课程与资料管理

- 多课程创建、切换、更新、删除与归档恢复。
- SQLite 保存结构化数据，课程文件和工作区保存在本地目录。
- 资料解析结果缓存，并区分 AI 可读与浏览器可预览状态。
- MarkItDown 为主解析链，按环境可使用 Docling、LibreOffice 转换。
- 扫描 PDF 和图片使用 RapidOCR 本地识别，文本过薄时可由视觉模型兜底。
- 资料内容可进入知识点、课程画像和生成工作流，并尽量保留来源关系。

### 4.2 复习策略与课程生成

- 生成课程画像、复习总计划与课程生成 Prompt。
- 支持在正式生成前与 AI 对话修改策略文档。
- 支持标准版、对话版、故事版三种课程内容风格。
- 故事版已加入连续情境、角色与概念映射等结构约束，并有相应质量校验。
- 支持增量生成与全部生成；当前推荐默认增量生成，先验证第一课质量。
- 支持后台持久任务、任务状态和失败信息。
- 最近已加入主模型与备用模型切换、调用量/失败量展示基础能力。
- 对不完整课程、模拟题、可读性、公式和章节结构已有多层校验与修复逻辑。

### 4.3 学习工作台

- 复习主线与每日任务。
- 基于知识前置关系的确定性调度和按日装包。
- 课程知识思维导图，支持章节/知识点下钻与掌握度展示。
- 刷题、即时讲评、作答记录、模拟卷和错题沉淀。
- 轻量笔记、划词摘录、知识点术语表。
- 多课程规划日历、课程计时器与学习时间日志。
- 浅色/深色主题、字号与字体设置。

### 4.4 AI 伴学

- SSE 流式对话与工具执行轨迹。
- 可更新任务状态、创建笔记和调整部分计划参数。
- 对重要计划变化支持“先生成提案、用户确认后应用”。
- 使用向量检索、摘要和历史召回保存长期学习上下文。
- 可选 MCP 外部来源能力仍保留，但个人版默认不依赖联网检索才能工作。

### 4.5 已实现但近期不扩建的基础

- 邮箱注册、登录、刷新、登出和本地 JWT 身份认证。
- 课程、归档和用户画像的数据归属隔离。
- SQLite WAL 与基础并发保护。

这些能力可以继续使用，但当前不应把它们扩展成校园平台。个人本地版允许只创建一个本地账号长期使用。

## 5. 本地数据与运行架构

### 5.1 技术栈

- 前端：React 19 + TypeScript + Vite。
- 后端：FastAPI。
- 数据库：SQLite（WAL）。
- 文件库：本机课程目录。
- OCR：RapidOCR + 可选视觉模型兜底。
- 模型接入：OpenAI 兼容接口，支持主模型和备用模型。

### 5.2 数据位置

主要本地数据：

- 数据库：`backend/data/exam_booster.db`
- 数据库 WAL 文件：`backend/data/exam_booster.db-wal`、`backend/data/exam_booster.db-shm`（运行时可能存在）
- 课程文件：`backend/data/courses/{course_id}/`
- 资料解析缓存：`backend/data/material_cache/`
- 向量缓存：`backend/data/embedding_cache.db`
- 模型资料：`backend/data/model_profiles.json` 与 `backend/.env`

个人版备份时应先停止后端，再整体备份 `backend/data/` 与 `backend/.env`，避免只复制主数据库而遗漏 WAL 中尚未合并的数据。

### 5.3 本地启动

后端：

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

前端：

```powershell
cd web
npm install
npm run dev
```

访问 `http://127.0.0.1:5173`。后端默认在 `http://127.0.0.1:8000`。

当前仅以单机、单个 FastAPI 进程为支持目标。不要为了“看起来像部署”而启动多 worker 或公网暴露端口。

## 6. 个人版近期路线图

### P0：稳定可用

- 修复现有回归测试中的后台课程生成兼容问题。
- 完成生成超时、重试、主备切换与前端状态显示的闭环。
- 确认取消、失败、部分完成和继续生成不会破坏已有课程。
- 对数据库、工作区 JSON、策略版本和课程正文做可恢复性检查。
- 为本地启动补充一键脚本或更清晰的启动检查。

### P1：课程质量

- 用至少 3 类真实课程验证资料解析：文字型、公式型、扫描型。
- 继续优化复习总计划，使任务量符合考试日期和每日时间预算。
- 分别验收标准版、对话版和故事版，不以单一 Prompt 样例代表全部课程。
- 让生成失败明确失败，不用低质量占位内容冒充成功。
- 完善小节级反馈、重写、版本冲突与回滚体验。

### P2：完整学习闭环

- 串通课程导入、策略确认、增量生成、学习、练习、错题和笔记。
- 校准掌握度更新和任务重排逻辑。
- 验证模拟卷评分、错题归档和再次练习。
- 改善空状态、加载状态、耗时提示、Token 使用与错误恢复提示。

### P3：个人版发布准备

- 固化依赖和本地安装流程。
- 提供数据备份、恢复、清空测试数据的操作说明。
- 准备一套可重复运行的个人版验收课程。
- 完成后再评估桌面封装；当前浏览器本地访问已经足够。

## 8. V1 验收标准

个人本地版 V1 达标需要同时满足：

1. 新电脑按文档可在本地完成安装、启动和登录。
2. 可创建多门个人课程，并稳定导入常见资料格式。
3. 解析失败时有清晰原因，不会静默生成空课程。
4. 至少一门真实课程可从资料导入完整走到策略、课程正文、练习与复盘。
5. 生成任务可查看状态；失败后可重试或继续，不破坏已生成内容。
6. 主模型异常时，备用模型能按预期接管或给出明确失败原因。
7. 增量生成可先生成一课，用户确认质量后再继续。
8. 计划总时长大体符合每日预算，知识前置顺序不明显错误。
9. 练习、模拟卷、错题、笔记和学习记录能正确保存并在重启后恢复。
10. 用户可按说明完成本地数据备份与恢复。
11. 后端测试全绿，前端类型检查和生产构建通过。
12. 不依赖公网部署、课程广场或管理后台即可独立使用。

## 9. 何时再考虑企业级升级

只有在以下条件基本满足后，才重新讨论校园版或企业级：

- 个人版真实使用稳定，核心流程没有频繁丢数据或生成中断。
- 课程内容质量达到可持续复习的水平。
- 本地安装、升级、备份和恢复已有清晰方案。
- 已有明确的多人共享需求和真实用户反馈，而不是预设需求。
- 有精力承担服务器安全、隐私合规、运维、成本和用户支持。

届时再单独立项评估 PostgreSQL、对象存储、任务队列、权限角色、课程广场、管理后台和云部署；不要提前把这些复杂度带回当前个人版。
