# 期末粥加速器 V1 方案

> **历史产品方案副本**：本文描述早期 Windows 本地单用户 V1 原型，用于保留产品演进依据；其中“不包含账号登录、云同步和多人协作”等边界不代表当前校园多用户版。当前定位与能力以根目录 `README.md` 为准。

## 1. 项目定位

“期末粥加速器”是一款面向大学生期末周冲刺的本地 AI Agent 学习工作台。

它服务于考试前 5-7 天、同时需要复习 6-10（时间天数仅供参考，实际由用户自己决定） 门课程的场景。用户将课程 PPT、平时练习、模拟卷和往年真题导入课程资料库后，系统通过资料分析、快速摸底、动态计划、定向练习和模拟演练，帮助用户围绕目标分数完成高效率复习。

V1 定位为可在实验室演示的 Windows 本地服务 + 浏览器界面原型，不包含账号登录、云同步和多人协作。

## 2. 核心目标

- 让用户在 10-15 分钟内完成单门课程的快速摸底，获得当前水平和预估分数区间。
- 基于课程考核方式、用户目标分数、可用复习时间和当前掌握度，生成可执行的复习主线。
- 让练习题和复习计划随学习表现动态调整，而不是固定不变的待办清单。
- 让 AI 伴学助手可以理解自然语言调整需求，但所有计划变更必须由用户确认后再生效。
- 所有资料、学习记录和 API Key 默认保留在本机；模型调用仅发送完成当前任务所需的资料片段。

## 3. 目标用户与典型场景

目标用户为平时听课较少、在期末前集中冲刺的大学生。

典型使用流程：

1. 新建课程，填写考试日期、考试形式、目标分数、每日可用时间和不考范围。
2. 上传 PPT、PDF、DOCX、图片等复习资料，或保存题目网址及用户摘录。
3. AI 分析资料，形成知识点、题型、分值倾向和重点章节的课程考核画像。
4. 完成 8-12 题、约 10-15 分钟的自适应摸底。
5. 查看预测分数、薄弱知识点和每日复习主线。
6. 在刷题、模拟卷、笔记、错题回顾中持续学习。
7. 根据作答结果动态更新掌握度，并生成新的计划调整建议。
8. 通过右侧 AI 伴学栏发出自然语言指令，例如“第四章老师说不考”“今天可以多学 1 小时”，确认提案后更新计划。

## 4. 功能结构

### 4.1 课程与资料库

每门课程独立管理以下信息：

- 课程名称、考试日期、考试形式和题型。
- 目标分数，例如“60 分通过”或“95 分以上”。
- 每日可用时间、总复习天数和个人补充说明。
- 明确不考、重点考或需要跳过的章节。
- 课程资料与解析结果。

V1 支持真实导入并解析：

- PDF：课件、试卷、真题、复习资料。
- PPTX：上课课件。
- DOCX：老师发放的练习和模拟卷。
- 图片：作业截图、题目截图。

资料解析需要保留页码、幻灯片序号或文件来源，便于计划、讲解和笔记回溯到原始材料。

网址在 V1 中只保存链接、备注与用户提供的摘录，不自动抓取网页正文，也不自动联网补充外部资料。

### 4.2 课程考核画像

AI 根据用户上传的资料生成单门课程的考核画像，包括：

- 知识点和章节结构。
- 高频考察知识点。
- 常见题型与题目风格。
- 试卷结构与可能分值倾向。
- 原题、例题和资料出处。
- 用户已明确排除的内容。

所有结论应尽量附带资料来源，避免 AI 脱离用户资料泛泛出题。

### 4.3 快速摸底

摸底采用 8-12 题的自适应小测，预计用时 10-15 分钟。

系统根据用户回答动态选择后续题目：答对则提高难度或扩展关联知识点，答错则继续定位薄弱环节。完成后输出：

- 预测分数区间与置信度。
- 各知识点掌握度。
- 优势项、薄弱项和高风险失分点。
- 与目标分数之间的差距。
- 建议优先复习的章节。

### 4.4 复习主线

复习主线是产品的核心页面，以“总览 + 每日计划”的方式组织。

每个任务包含：

- 对应知识点和学习目标。
- 预计时长。
- 关联资料出处。
- 学习、练习和复盘入口。
- 当前完成状态。

任务优先级由以下因素综合决定：

`课程考核权重 × 薄弱程度 × 目标分差 × 剩余时间压力`

例如，用户目标为 60 分时，系统优先保障基础题和高分值核心内容；用户目标为 95 分时，系统增加综合题、易错点、边缘章节和模拟卷演练。

### 4.5 刷题练习

刷题模块包含两类题目：

- 用户资料中提取的原题、练习题和真题。
- AI 按用户资料中的知识点、难度和题型风格生成的仿题。

支持客观题自动判分。主观题由 AI 根据资料依据进行评分、讲评和步骤分析。

每次作答会更新对应知识点掌握度。若用户持续在同一知识点出错，系统应提高该知识点在后续练习与复习计划中的占比。

### 4.6 模拟卷演练

模拟卷根据课程考核画像进行限时组卷，可混合用户资料原题与 AI 仿题。

完成后提供：

- 客观题自动判分。
- 主观题 AI 评分与讲评。
- 分题型、分知识点的得分分析。
- 错题自动归档。
- 针对下一阶段计划的调整建议。

### 4.7 复习笔记

笔记采用轻量编辑模式，支持：

- 自由记录复习内容。
- 关联知识点标签。
- 跳转到相关资料、题目和错题。
- 从 AI 讲解或错题分析中快速沉淀内容。

### 4.8 错题回顾

错题由系统自动记录，也支持用户二次编辑维护。

每道错题可保存：

- 原题和用户答案。
- 正确答案与讲解。
- 错误原因。
- 关联知识点和题型。
- 复习状态与再次练习记录。

AI 将错题归因为概念不清、公式遗漏、审题失误、计算错误、记忆缺失或综合应用不足，并用于调整练习策略。

### 4.9 AI 智能伴学侧栏

右侧常驻 AI 伴学栏负责解释、答疑和计划协商。

支持的指令包括：

- “第四章老师说不考，删掉它。”
- “今天时间充裕，再安排 1 小时。”
- “我只求及格，先把最稳的题型学会。”
- “这个知识点我已经会了，少出一点题。”

AI 不直接静默修改计划，而是生成可解释的调整提案，展示：

- 调整原因。
- 受影响任务。
- 调整前后的时间差异。
- 预计收益或风险。

用户确认后，系统才写入新计划，并保留调整记录。

## 5. Agent 设计

本项目的 AI Agent 不应只是聊天窗口，而应是具有明确状态、工具和记忆的学习编排系统。

V1 采用受控的结构化 Agent 流程，主要能力包括：

1. 资料分析：从文件中提取文本、题目、知识点、题型和来源。
2. 课程画像：生成课程的知识点结构与考核方式。
3. 摸底出题：根据当前答题结果选择下一题。
4. 计划生成：根据目标、时间、考核权重和掌握度生成每日任务。
5. 练习与讲评：生成或选择题目，评分并解释错误原因。
6. 模拟卷组卷：根据考核画像生成限时模拟卷。
7. 动态调整：根据学习表现和自然语言指令生成待确认的调整提案。

所有 Agent 输出应使用结构化数据，并尽量关联课程资料来源。V1 不必引入复杂的多 Agent 框架；以可控的后端工作流、明确的工具边界和本地记忆为优先。

## 6. 本地学习记忆

系统需要为每个用户、每门课程保留独立学习记忆，核心数据包括：

- `ModelProfile`：模型厂商、Base URL、模型名、视觉能力、连接状态。
- `CourseSetup`：课程设置、考试信息、目标分数、每日时间和排除项。
- `Material`：原始资料、解析结果、页码或幻灯片来源。
- `KnowledgePoint`：知识点、关联资料和考核权重。
- `ExamBlueprint`：题型、分值倾向、出题风格和课程考核画像。
- `QuestionAttempt`：题目、作答、得分、讲评和耗时。
- `MasteryRecord`：知识点掌握度、最近证据、错因和复习优先级。
- `Plan` 与 `PlanTask`：复习计划、每日任务和完成状态。
- `Note`：复习笔记及关联对象。
- `Mistake`：错题、错因、复练状态和标签。
- `PlanAdjustmentProposal`：计划调整前后内容、确认状态和触发原因。

## 7. 技术方案

### 7.1 技术栈

- 前端：React + TypeScript + Vite。
- 后端：FastAPI。
- 数据库：SQLite。
- 文件库：本地文件夹存储课程资料与解析产物。
- 模型接入：统一 OpenAI 兼容接口适配层。
- 部署形态：Windows 本机启动后，通过浏览器访问 `localhost`。

### 7.2 模型配置

V1 提供以下模型配置方式：

- GPT 预设。
- DeepSeek 预设。
- GLM 预设。
- OpenAI 兼容自定义配置：`Base URL + API Key + 模型名`。

每个配置应支持连接测试，并标记当前模型是否支持图片理解。API Key 默认仅保存在本机，不上传到云端。

### 7.3 文件解析

后端负责将不同格式资料统一为可检索的课程内容片段：

- PDF：提取文本、页码和必要的题目区域。
- PPTX：提取每页幻灯片的标题、正文和备注。
- DOCX：提取正文、表格与题目结构。
- 图片：先进行本地 OCR；涉及图表、公式或示意图理解时，只有当前模型支持视觉能力才进行视觉分析。

解析结果需要保留与原文件的映射关系，以支持“这条计划来自哪一页 PPT”“这道题参考了哪份真题”的可追溯体验。

## 8. 前端信息架构

可以参考项目中的两张图片。

视觉采用已确认的活泼、紧凑三栏工作台：

- 左侧：课程列表、课程概览和五个学习模块入口。
- 中间：复习主线、今日任务、掌握度、练习和模拟卷等主要工作区。
- 右侧：常驻 AI 伴学栏、对话记录和待确认的计划调整提案。

核心模块入口：

1. 复习主线。
2. 刷题练习。
3. 模拟卷演练。
4. 复习笔记。
5. 错题回顾。

桌面端提供完整流程。移动端 V1 只保证查看计划、完成打卡和 AI 对话可用。
同时要有浅色模式和深色模式两种主题色

## 9. V1 范围与非目标

V1 必须完成：

- 多课程本地管理。
- 本地资料导入与解析。
- 课程考核画像。
- 自适应摸底。
- 按目标与时间生成复习计划。
- 定向刷题、模拟卷、笔记和错题回顾。
- 基于作答表现的计划调整提案。
- AI 侧栏自然语言调整与用户确认机制。
- GPT、DeepSeek、GLM 与自定义 OpenAI 兼容接口配置。

V1 暂不包含：

- 用户登录、云同步和多人协作。
- 自动联网检索外部资料。
- 自动抓取用户提供网址的网页正文。
- 移动端完整编辑体验。
- 公开部署和商业化支付功能。

## 10. V1 验收标准

1. 用户可为多门课程分别建立资料库，并成功导入 PDF、PPTX、DOCX 和图片。
2. AI 能生成包含知识点、题型与资料出处的课程考核画像。
3. 用户完成一次 10-15 分钟摸底后，可获得分数预测、薄弱项和复习优先级。
4. 用户设置三天或五天的每日学习时间后，系统生成的计划总时长不超过每日预算。
5. 当用户连续做错同一知识点时，后续刷题与计划会出现针对该知识点的强化建议。
6. 用户完成模拟卷后，可查看评分、讲评、错题和后续调整建议。
7. 用户通过 AI 侧栏提出“删除不考章节”或“增加今日 1 小时”等要求时，系统只生成调整提案；确认后计划才改变。
8. 全部课程资料和学习记录默认保存在本机。
